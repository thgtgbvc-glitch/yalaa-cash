# ملاحظات التنفيذ والقرارات

## البنية المعتمدة

المشروع يحتوي تطبيقين مستقلين للمستخدم النهائي، ولوحة تحكم، وحزمة مشتركة:

```text
تطبيق الزبون ──┐
تطبيق المحل ───┼── yalla_cash_core ── Backend واحد
لوحة التحكم ───┘
```

الحزمة المشتركة تحتوي النماذج وقاعدة حساب العمولة والثيم ومستودع بيانات العرض. طبقة الربط الجديدة تعتمد `YallaCashRepository` مع تنفيذين: `RemoteYallaCashRepository` للـBackend و`InMemoryYallaCashRepository` للعرض.

تمت إضافة Backend مستقل داخل `backend/nestjs`، وأصبحت حزمة `yalla_cash_core` تحتوي طبقة Clean Architecture للربط:

- `YallaCashRepository` كعقد Domain واحد للتطبيقات الثلاثة.
- `RemoteYallaCashRepository` لاستهلاك REST API.
- `InMemoryYallaCashRepository` لتشغيل نفس Cubits فوق بيانات العرض.
- `YallaCashApiClient` لإدارة HTTP وJWT refresh والأخطاء.
- `CustomerAppCubit`, `MerchantAppCubit`, `AdminAppCubit` لإخراج حالات loading/success/empty/failure من الواجهات.

ملفات الواجهات الحالية لا تزال محافظة على التصميم وتستخدم `YallaCashStore.demo()` مباشرة. الخطوة التالية داخل Flutter هي نقل كل شاشة لاستهلاك Cubit المناسب عبر `YallaCashRuntime.fromEnvironment()` بدون تغيير الشكل البصري.

## قرارات تم تصحيحها عن النموذج التجريبي

1. كل عملية تحفظ `commission_rate_snapshot` حتى لا تتغير فواتير الماضي عندما يغيّر الأدمن نسبة المحل.
2. العملية ترتبط بـ`store_id` و`customer_id` بدلاً من اسم المحل.
3. كل عملية تحمل `idempotency_key` لمنع تكرار الفاتورة بسبب ضعف الإنترنت أو النقر المتكرر.
4. حركة النقاط لها Ledger مستقل، وليس رقماً قابلاً للتعديل بلا أثر تدقيقي.
5. طلب الكاش يحجز النقاط أثناء الانتظار، ثم يخصمها عند التسوية أو يحررها عند الرفض.
6. شرط الحصرية ممثل بفهرس فريد: محل نشط واحد لكل مدينة/فئة.
7. QR التجريبي ليس آمناً للإنتاج. يجب أن يصدر الخادم رمزاً موقّعاً وقصير الصلاحية، ويمنع إعادة استخدامه.
8. Backend الجديد يصدر QR موقّعاً وقصير الصلاحية عبر `POST /customer/qr-token`.
9. تسجيل الفاتورة في Backend الجديد لا يقبل نسبة العمولة أو النقاط من تطبيق المحل.
10. قاعدة البيانات تحتوي فهارس جزئية للحصرية وطلب الكاش المعلق الواحد.

## نقطة تحتاج تثبيتاً تجارياً

الملف الأصلي يقول إن نصف العمولة يتحول إلى نقاط، لكنه يعرّف أيضاً قيمة نقدية للنقطة. للحفاظ على نصف العمولة فعلياً:

```text
customer_points = round((commission / 2) / point_value_syp)
```

النسخة الحالية تطبق هذه القاعدة. إذا كان المقصود نظاماً تسويقياً مختلفاً، يجب تعريف «كم ليرة تمنح نقطة واحدة» و«كم ليرة تساوي النقطة عند الاستبدال» كقيمتين منفصلتين.

## قبل الإنتاج

- نقل واجهات Flutter الحالية من `YallaCashStore.demo()` إلى Cubits الجديدة.
- ضبط مزود SMS فعلي عند إطفاء `OTP_DEV_MODE`.
- ضبط Firebase Admin في الإنتاج للتحقق من Google/Facebook OAuth.
- إضافة تخزين الصور.
- إضافة إشعارات FCM.
- إضافة اختبارات تكامل مع قاعدة تجريبية.
- مراجعة قانونية ومالية لطريقة عرض الكاش باك وحفظ بيانات الهاتف.
