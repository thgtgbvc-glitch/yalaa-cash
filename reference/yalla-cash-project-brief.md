# يلا كاش — ملف تعليمات تقني (Project Brief)

> هاد الملف مرجع كامل لمنطق العمل (Business Logic) المتفق عليه، مبني على نموذج تفاعلي (React Prototype) جاهز بالمرفقات: `yalla-cash-prototype-v3.jsx`. استخدمه كأساس للتصميم البصري والتدفق، وابنِ عليه تطبيق حقيقي (React Native / Flutter) + Backend + لوحة تحكم ويب.

---

## 1. فكرة المشروع

منصة كاش باك وولاء (Loyalty & Cashback) تربط بين محلات تجارية وزبائن:
- المنصة تتفق مع **محل واحد حصري لكل قطاع/فئة بكل مدينة** (مطعم واحد، ماركت واحد، صيدلية واحدة... إلخ) — هاي الميزة التنافسية الأساسية.
- عند الشراء، الزبون يعرض QR الخاص فيه، المحل يمسحه ويدخل قيمة الفاتورة.
- المنصة تحسب عمولة % من الفاتورة (نسبة مختلفة لكل محل، يحددها الأدمن).
- العمولة تنقسم: نص للمنصة (دخل)، ونص يتحول لـ"نقاط" تنضاف لمحفظة الزبون.
- الزبون يستبدل نقاطه إما بمنتجات رقمية (رصيد اتصالات، قسائم، اشتراكات) أو **كاش نقدي فعلي** (بعد موافقة الإدارة).
- المحل يتحاسب مع المنصة **نقدًا مرة بالشهر** بناءً على مجموع عملياته.

**العملة**: الليرة السورية فقط، مافي دعم لعملات ثانية.

## 3. نماذج البيانات الأساسية (Data Models)

### User (Customer)
```
id, name, phone (nullable), auth_method (facebook | gmail | phone),
governorate, points_balance, created_at
```

### Store (Merchant)
```
id, name, category, commission_rate (%), description, location,
image_url, is_active, created_at
```

### MerchantAccount (تسجيل دخول التاجر)
```
id, store_id, email, password_hash, created_at
```

### Device (لتتبع الأجهزة المسجّلة لكل حساب تاجر)
```
id, merchant_account_id, device_label, last_login_at
```

### Transaction (فاتورة/عملية بيع)
```
id, store_id, customer_id, amount (SYP), commission_amount,
customer_points_earned, created_at
```

### DigitalProduct (منتج رقمي قابل للاستبدال)
```
id, name, cost_in_points, image_url, requires_phone_number (bool), is_active
```

### ProductRedemption (استبدال منتج رقمي)
```
id, customer_id, product_id, phone_number (nullable), created_at
```

### CashRedemptionRequest (طلب استبدال نقاط بكاش)
```
id, customer_id, points_requested, cash_value (SYP),
status (pending | settled | rejected), created_at, settled_at
```

### PlatformSettings (إعدادات عامة، صف واحد أو key-value)
```
point_to_cash_rate (SYP per point)
```

## 4. منطق الحسابات (Business Logic)

```
عند تسجيل فاتورة بقيمة X من محل نسبته العمولة R%:
  commission = X * (R / 100)
  customer_points_earned = round(commission / 2)
  platform_revenue = commission - customer_points_earned   // (تقريبًا، أو نص/نص حسب دقة التقريب)

عند طلب استبدال نقاط بكاش (N نقطة):
  cash_value = N * point_to_cash_rate
  → الطلب يبقى "pending"، والنقاط تُحجز (لا تُخصم فعليًا من رصيد الزبون بعد)
  → عند موافقة الأدمن ("تمت المحاسبة"): تُخصم النقاط نهائيًا من رصيد الزبون
  → عند الرفض: الطلب يُلغى، النقاط ترجع متاحة (ما كانت انخصمت أصلًا)

رصيد الزبون "المتاح" للاستبدال = points_balance - (مجموع النقاط بطلبات pending الخاصة فيه)

التحاسب الشهري لكل محل:
  total_sales = مجموع فواتيره بالشهر
  commission_due = total_sales * (commission_rate / 100)
  → يُدفع نقدًا، ويُحدَّد "مسدد" من لوحة التحكم
```

## 5. شاشات تطبيق الزبون

1. **تسجيل/دخول** (أول ما يفتح التطبيق):
   - اختيار طريقة: فيسبوك / جيميل (OAuth حقيقي) أو رقم الهاتف (OTP حقيقي)
   - إدخال الاسم + المحافظة (قائمة محافظات سوريا)
   - إنشاء الحساب
2. **الرئيسية**: رصيد النقاط + قائمة المحلات الحصرية (بالتصنيف)، كل محل قابل للضغط لعرض وصفه وموقعه
3. **كودي**: QR شخصي ثابت لكل مستخدم يعرضه عند الدفع
4. **المحفظة**: سجل كل العمليات (تاريخ، محل، قيمة الفاتورة، نقاط مكتسبة)
5. **المتجر**:
   - بطاقة "استبدال نقاط بكاش" (إدخال عدد النقاط → يحسب القيمة النقدية → إرسال طلب)
   - قائمة منتجات رقمية للاستبدال (بعضها يطلب رقم هاتف، مثل رصيد الاتصالات)
6. **قائمة إعدادات** (☰): اللغة، الوضع الداكن، تواصل معنا، تقييم التطبيق، مشاركة التطبيق، رابط التحميل من المتجر، تسجيل الخروج

## 6. شاشات تطبيق المحل

1. **تسجيل دخول**: بريد إلكتروني + كلمة مرور (تُصدر من لوحة التحكم فقط، لا يوجد تسجيل ذاتي للتاجر) — دعم تسجيل دخول من أكثر من جهاز بنفس الحساب
2. **الرئيسية/الإحصائيات**: عدد المبيعات، قيمة المبيعات (ل.س)، العمولة المستحقة (ل.س) — حسب نسبة عمولة هالمحل تحديدًا
3. **مسح QR**: مسح كود الزبون بالكاميرا
4. **إدخال الفاتورة**: إدخال قيمة الفاتورة بالليرة السورية → تأكيد
5. **شاشة نجاح**: تعرض فقط "العمولة المستحقة عليك" (مو تفاصيل تقسيمها)، مع ملاحظة إن التحاسب نقدًا مطلع الشهر

## 7. أقسام لوحة التحكم (Admin Dashboard)

1. **إعدادات عامة**: قيمة النقطة نقدًا (ل.س)
2. **المستخدمون**: قائمة كل الزبائن (الاسم، المحافظة، الرصيد، تاريخ الانضمام) + إمكانية منح نقاط / خصم نقاط / حذف مستخدم
3. **طلبات استبدال النقاط بكاش**: إشعار باسم الزبون وعدد النقاط والقيمة، مع زرّي "تمت المحاسبة - حذف النقاط" و"إلغاء الطلب"
4. **إدارة المحلات**: إضافة محل جديد، تعديل الاسم/القطاع/الوصف/الموقع/الصورة، **تحديد نسبة عمولة مستقلة لكل محل**
5. **حسابات دخول المحلات**: توليد أكثر من بريد إلكتروني لنفس المحل (لأكثر من فرع/جهاز)، عرض عدد الأجهزة المسجّلة لكل حساب
6. **إدارة المنتجات الرقمية**: إضافة/تعديل منتجات الاستبدال (الاسم، التكلفة بالنقاط، الصورة، هل يتطلب رقم هاتف)
7. **التحاسب الشهري**: لكل محل — عدد العمليات، مجموع المبيعات، العمولة المستحقة، زر "تحديد كمسدد"

## 8. المصادقة الحقيقية المطلوبة (غير موجودة بالنموذج التجريبي)

- تسجيل دخول فيسبوك/جيميل عبر OAuth حقيقي (Firebase Auth أو مشابه سهل وسريع للتطبيق)
- تسجيل دخول برقم الهاتف عبر OTP/SMS حقيقي (خدمة مثل Twilio أو مزود محلي)
- تسجيل دخول التاجر: بريد + كلمة مرور مع تشفير حقيقي (bcrypt) + JWT tokens
- QR: يفضّل أن يكون كود مشفّر/موقّع (مو رقم عشوائي) لمنع التزوير

## 9. ملاحظات تقنية عامة

- **الاقتراح للـ Backend**: Node.js + Express/Fastify أو Firebase (Firestore + Functions) للسرعة بالمرحلة الأولى
- **قاعدة البيانات**: PostgreSQL (لو Backend مستقل) أو Firestore (لو Firebase)
- **الموبايل**: React Native (الأقرب لكود النموذج التجريبي الحالي React، يسهّل إعادة استخدام منطق الواجهة)
- **لوحة التحكم**: تطبيق ويب منفصل (React/Next.js) يتصل بنفس الـ API
- **الإشعارات** (لطلبات الكاش وغيرها): Firebase Cloud Messaging أو مشابه
- النموذج المرفق `yalla-cash-prototype-v3.jsx` يحوي كل الشاشات والـ CSS والألوان (أزرق سماوي + أبيض) — استخدمه كمرجع تصميم بصري مباشر (design reference)، مو للتشغيل بالإنتاج.

## 10. أولويات مقترحة لمرحلة أولى (MVP)

1. تسجيل دخول زبون (رقم هاتف كافي بالبداية) + تسجيل دخول تاجر
2. QR + مسح + تسجيل فاتورة + حساب عمولة ونقاط
3. لوحة تحكم: إدارة محلات + مستخدمين + تحاسب شهري
4. استبدال نقاط بكاش (بدون منتجات رقمية بالبداية)
5. لاحقًا: منتجات رقمية، فيسبوك/جيميل OAuth، تعدد الأجهزة
